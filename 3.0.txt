あなたは、ブラウザで動く高性能な Minecraft 風ブロックゲームを作るエンジニアです。  
以下を厳守し、最終成果物は **単一HTMLファイル1本のみ** で出力してください。  
目的は、派手さより **軽量・安定・完成度・編集性・実動FPS** を最優先することです。

【最重要目標】
- 単一HTMLで動く Minecraft 風ブロックゲームを作る
- PC / スマホ両対応
- できるだけ広いワールドに見える
- ブロック設置・破壊、水、洞窟、山、バイオームを実装
- プレイヤーはクリエイティブ前提
- Shiftダブルタップで飛行ON/OFF
- 水中では浮力が働き、沈みすぎず自然に浮く
- Minecraft本体の完全再現ではなく、**単一HTMLで安定して動く軽量近似版** を目指す
- **1ブロック=1メッシュは禁止**

【技術条件】
- HTML + CSS + JavaScript（ES2022以降）
- WebGL2 前提、Three.js を第一候補
- 外部依存は極力禁止。許容は必要なら Three.js 本体1つまで
- 外部画像・音声・モデル・JSON禁止
- procedural generation / inline data / data URI / canvas生成を優先
- WebGPU / TypeScript / React / Vue / ビルド工程 / WASM前提は禁止
- 入力は可能な限り Pointer Events ベースで共通化

【基本性能目標】
- Medium品質・初期地点付近で平均60fps目標
- draw calls は可能な限り 200 未満
- visible chunks は上限管理
- dirty chunk 再メッシュ化は時間予算制
- render distance と simulation distance を分離
- 通常プレイ中は**ユーザーが選んだ解像度を勝手に落とさない**
- 軽量化はまず構造最適化で達成する
- WebGL2 非対応時は軽量エラー表示で停止
- Worker / OffscreenCanvas 非対応なら main thread fallback

【ゲーム仕様】
- 一人称視点
- PC操作モード / スマホ操作モード / AUTO を用意
- PC: Pointer Lock + WASD + マウス視点
- W前進 / A左 / S後退 / D右
- Space: ジャンプ / 水中上昇 / 飛行上昇
- Shift/Ctrl: しゃがみ / 水中下降 / 飛行下降
- 左クリック: 破壊
- 右クリック: 設置
- 数字キー / ホイール: ブロック選択
- Shiftダブルタップで飛行ON/OFF
- スマホ: 仮想スティック、視点ドラッグ、ジャンプ、破壊、設置、ブロック選択、飛行切替UIを用意
- 飛行中は自由移動できるが操作しやすくする
- ブロック種類は **ちょうど10種類**
- 例: 草、土、石、砂、水、木、葉、ガラス、雪、レンガ
- X, Y, Z と Height(Y) を表示可能にする
- F3でデバッグ表示切替

【ワールド高さ】
- 標準高さプリセット: 地下 -40 / 地上 200
- 特大高さプリセット: 地下 -40 / 地上 350
- 特大では、高山・巨大な尾根・深い谷・複雑で立体的な地形・絶景が出やすいようにする
- 高さだけ伸ばすのではなく、山の最大高度、地形の縦変化量、谷と尾根のコントラスト、山岳帯の出現率も連動調整する
- ただし山だらけにはせず、平地・丘陵・山岳・谷・海岸の対比を残す
- 高さ設定はワールド生成前のみ変更可能、生成後は変更不可

【地形生成方針（最重要）】
- 単純な2D高さマップだけで地形を作ってはいけない
- Minecraft 1.18+ 風に、**複数の大域ノイズ + 3D密度場** で地形を作る
- seed固定の deterministic generation にする
- continentalness 相当で海・海岸・内陸
- erosion 相当で平坦さ/険しさ
- ridges / peaks-and-valleys 相当で山脈・峰・谷
- それらから base height と mountain factor を決める
- final density > 0 なら地形、<= 0 なら空気
- 3D density により崖、張り出し、複雑断面、オーバーハングを可能にする
- 別の3D cave noise で地下洞窟を生成
- sea level を定義し、海面以下の低地や空洞には水を入れる
- surface rules で草、土、石、砂、雪などを貼り分ける
- biome は地形形状そのものではなく、主に表層・植生・色味・地形傾向に使う
- 地上には複数バイオームを実装（平原、森林、砂漠、雪原、丘陵/山地など）
- ワールドは全域保持せず、プレイヤー近傍チャンクのみ生成・保持・描画・再メッシュ化する

【洞窟設定の追加】
- ワールド生成前に、洞窟の **生成量（数）・規模（大きさ）・複雑度（分岐/入り組み具合）** を独立して可変にできるようにする
- これは既存の洞窟生成アルゴリズムそのものを壊さず、**上位パラメータ**として作用させること
- つまり中核ロジックは保ちつつ、出現頻度・空洞の広がり・接続性や枝分かれ傾向を外部設定で調整できる構造にする
- 洞窟設定はワールド生成前のみ変更可能、生成後は変更不可
- 地形破綻を防ぐため安全な範囲で制限する

【チャンク読み込み設定】
- 読み込みチャンク数は 1～30 で可変
- ワールド生成前に選択可能
- ワールド生成後も設定画面から変更可能
- 読み込みチャンク数は render distance と整合させる
- 1 は超軽量、30 は超広域だが高負荷であることを明示する

【解像度設定】
- 解像度プリセット: XLOW / LOW / MEDIUM / HIGH / XHIGH / ULTRA
- ワールド生成前に選択可能
- ワールド生成後も設定画面から変更可能
- 表示サイズではなく内部描画解像度/品質で制御する
- ただし通常プレイ中は、**軽量化のために解像度を勝手に落とさない**
- 自動品質調整を入れる場合も、解像度自動低下はデフォルトOFF
- 軽量化は解像度ではなく構造最適化を優先

【ワールド生成画面 / 設定画面】
- ワールド生成前に専用画面を用意
- 選べる項目:
  - ワールドシード
  - 読み込みチャンク数（1～30）
  - 解像度プリセット
  - ワールド高さ
  - 操作方式（AUTO / PC / MOBILE）
  - 洞窟数・大きさ・複雑さ
- ワールド生成後に変更可能:
  - 読み込みチャンク数
  - 解像度
  - 操作方式
  - スクリーンショット品質
  - スクリーンショット影設定
- ワールド生成後に変更不可:
  - ワールド高さ
  - 洞窟生成設定
- 設定画面はプレイ中いつでも開けるようにする

【解像度を損なわない軽量化（最重要）】
- 軽量化は **解像度低下ではなく構造** で行う
- visible faces only を徹底し、内部面は絶対に作らない
- 可能なら greedy meshing を使い、同条件の隣接面を矩形結合する
- terrain は chunk 単位の custom BufferGeometry で描画
- 小物や繰り返し要素は InstancedMesh / 同等手法で描画
- 同一マテリアルで形だけ違う群れは BatchedMesh / 同等手法で draw call 削減
- texture atlas でマテリアル切り替え最小化
- 非空チャンクのみ保持
- 変更時は dirty chunk queue により必要チャンクだけ再メッシュ化
- フラスタム外チャンクは描画しない
- render distance / simulation distance を分離
- worker に地形生成や再メッシュ化を逃がしてよい
- 毎フレーム大量 new 禁止、TypedArray / Vector / Ray / 一時配列は使い回す
- geometry / material / texture / render target のライフサイクル管理を徹底
- 通常プレイ中は fragment shader、透明物、影、ポストプロセスを極力軽くする
- 軽量化の主手段を「画面解像度低下」にしてはいけない

【スクリーンショット強化（最重要）】
- 通常描画とは別に、**スクリーンショット専用の高品質再レンダリング経路**を実装する
- スクショ時はゲームを一時停止してよい
- 現在カメラから見えている visible chunk を中心に、高品質再描画する
- 低解像度の現在表示を単純保存するのではなく、**撮影時だけ別品質で再レンダリング**する
- オフスクリーン描画（WebGLRenderTarget 等）を使ってよい
- 保存は PNG 優先、可能なら toBlob / convertToBlob を優先

【スクショの明るさ・全画面高精細化】
- スクショは通常表示よりやや明るく、見やすくしてよい
- スクショ時のみ tone mapping / exposure を強化してよい
- ACES系など見栄えの良い tone mapping を使ってよい
- 白飛びしすぎないこと
- **現在の画面全体の構図をそのまま保持したまま** 高解像度化すること
- 勝手にトリミングしない
- 画面の一部だけ別構図で描き直さない
- 最優先は「現在視点そのものを高解像度で再レンダリングすること」
- 完全再レンダリングが不可能な環境では、全画面アップスケールをフォールバックとして使ってよい
- その場合も画面全体を均一に正確アップスケールすること

【超高解像度スクショ仕様】
-4K / 6K / 8K 相当の出力プリセットを用意してよい
- ULTRA時は可能なら 8K 級を目指してよい
- ただし WebGL 上限を実行時に確認し、無理なら安全にフォールバックする
- 少なくとも MAX_TEXTURE_SIZE / MAX_RENDERBUFFER_SIZE / MAX_VIEWPORT_DIMS を考慮する
- 単一巨大バッファで無理ならタイル分割レンダリングで合成してよい
- 通常プレイの解像度とは独立して、スクショだけ高解像度化する

【スクショ時だけの高品質ブロック化】
- スクショ時のみ、見えているブロックを高品質版で再描画してよい
- 低解像度atlasを単純拡大して済ませてはいけない
- block ID と seed に基づいて高品質 procedural texture を再生成してよい
- スクショ時のみ normal / bump map で凹凸感を強化してよい
- さらに可能なら displacement または高分割ジオメトリで本当の凹凸を作ってよい
- ただし高分割化は visible faces や重要面のみ
- 不安定なら true displacement より normal/bump 強化を優先

【スクショ時だけの極リアルな影】
- 通常プレイ時は影をオフ、またはごく軽量にする
- **高解像度ゲーム内スクリーンショット時のみ**、極リアルな影を一時的に有効化してよい
- DirectionalLight の高品質シャドウマップを使ってよい
- 影解像度や shadow filter をスクショ時だけ強化してよい
- castShadow / receiveShadow 対象をスクショ時だけ増やしてよい
- 対象は原則、現在見えている範囲と重要オブジェクトに限定する
- スクショ時のみ軽いAO強化を併用してよい
- bloom / SSR / DOF / volumetric / motion blur は引き続き原則禁止
- 撮影後は必ず通常の軽量影設定へ戻す
- OFF / SOFT / REALISTIC / EXTREME などの段階を用意してよい

【通常プレイ時の描画制約】
- postprocess は通常プレイ時には使わない
- 通常プレイ時の影は原則オフ
- 点光源シャドウは禁止
- 半透明を乱用しない
- 水面も軽量表現にする
- overdraw を増やす表現を避ける
- 通常プレイ時にリアルな影や重い材質を常駐させない

【禁止事項】
- 1ブロック=1Mesh、1面=1Mesh
- ワールド全体の毎回再構築
- 変更1回で全チャンク再メッシュ
- 単純2D高さマップだけで「マイクラ風地形」とすること
- 通常プレイ中に高価な影を常時有効化
- 通常プレイ中に勝手に解像度を落として軽量化したことにすること
- 外部モデル依存、巨大テクスチャ、PBR多用
- 毎フレーム大量GC / 重いDOM更新 / GPU readback
- コード完全重複による PC版 / スマホ版分裂
- 低解像度現在表示を単純拡大して「超高解像度スクショ」と呼ぶこと
- スクショで構図を勝手に変えること
- 複数ファイル出力
- TODOや未完成の仮置き

- 地上バイオームがある
